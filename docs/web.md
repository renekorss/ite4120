# English web demo

Run `./scripts/start-web.sh` from the root, then open the **Local** URL printed by Vite in a current browser. The default is http://127.0.0.1:5173. If that port is occupied, the same command selects a free port. Browser permissions and push subscriptions belong to the chosen origin. This local-only stack uses React, TypeScript, Vite, the versioned API, PostgreSQL, and synthetic X-Road data. Session tokens live in memory. Reloading the page requires signing in again. Browser notification permission and subscriptions survive tab closure.

## Test accounts

Select Smart-ID, Mobile-ID or ID-card on the login screen. All three choices open the same local demo-code flow. The codes are public demo selectors. Testers share the synthetic state of each account. The server accepts only enabled, seeded accounts with the synthetic issuer. It applies source throttling and issues revocable, user-scoped sessions. The web overlay explicitly enables the route; the standalone API returns 404. English client requests send `Accept-Language: en`. Other API consumers retain their default locale.

| Code | Scenario |
| --- | --- |

| 00000000002 | Expiring licence. Refresh to get a deadline 30 days from today. |
| 00000000003 | Expired licence |

Demo setup preserves prior history and preferences. In the web stack a refresh checks both the licence and synthetic medical registries. A failed lookup retains the previous successful snapshot. The mock licence date for code 02 is relative to refresh time. The medical expiry date is relative to the demo’s pinned reference date. See the [mock integration contract](xroad-mock.md#supplemental-medical-registry-for-the-browser-demo).

## Scheduled browser notifications

1. Open the demo in a normal browser profile. Use code 00000000002, select **Refresh data**, then **Reminders**.
2. Turn on reminders or connect this browser, grant notification permission and select **30 days before**. Save the settings. The next worker pass can run immediately after enabling a due interval.
3. Close the app tab while the browser stays running. The worker normally polls every 30 seconds. Following a notification opens renewal guidance after login. History records when the push provider accepted delivery.
4. Verify the same account/deadline/interval appears once. Replaying the test on the same date will reuse this history. Use a fresh disposable database for repeatable delivery acceptance tests.

The database's unique logical reminder key allows one notification per account, document kind, deadline and lead time. The scheduler chooses the most recently created active subscription for the account. It checks current verified document dates, preferences and subscription status again immediately before sending. Each pass recovers due reminders throughout their UTC calendar day. Dates from older superseded snapshots are excluded. Provider acceptance and confirmed desktop display are separate observations.

Subscriptions contain endpoint and encryption keys and use the existing encrypted subscription store. VAPID uses a separate P-256 private key in the ignored secret directory. The sender uses encrypted Web Push with a five-second provider timeout and 24-hour message TTL. Only exact HTTPS provider hosts on port 443 are allowed. Redirects are disabled. A 404/410 revokes the subscription. Explicit 429/5xx responses retry after the configured interval. An ambiguous timeout or interrupted attempt is marked unconfirmed. The worker avoids sending another copy automatically. Review uncertain attempts with the operator before considering recovery.

## Operations

All web settings belong to the local deployment operator. Restart/recreate the affected services after changing a setting.

| Setting | Default or location | Purpose |
| --- | --- | --- |
| DEMO_CODE_LOGIN | Off in standalone API, 1 in web overlay | Synthetic allowlisted code login in development/test |
| VAPID_KEY_FILE | /run/secrets/vapid_key in web overlay | Persistent private signing key generated by init-local.sh |
| VAPID_SUBJECT | mailto:demo@example.test | Sender contact; supply a monitored contact for an operational deployment |
| WEB_PUSH_HOSTS | fcm.googleapis.com,updates.push.services.mozilla.com,web.push.apple.com | Sets the web stack's exact PUSH_ALLOWED_HOSTS |
| REMINDER_POLL_SECONDS | 30 | Seconds between scheduler passes |
| REMINDER_RETRY_SECONDS | 300 | Delay after an explicitly retryable provider response |
| API_PROXY_TARGET | Published local API address detected by start-web.sh | Vite server proxy for same-origin /api requests |

The web overlay leaves runtime database access with the limited API role. Audit records use `push.delivery` with a random attempt trace and a safe outcome/error code. Existing subscription, history, attempt and audit retention rules apply. Keep VAPID and subscription-encryption keys out of Git, logs, and exported artifacts. Changing the VAPID key requires reconnecting browsers. Use synthetic data only in this deployment.

The following commands assume a shell at repository root:

```sh
export COMPOSE_FILE=compose.yaml:compose.mock.yaml:compose.api.yaml:compose.web.yaml
docker compose ps
docker compose logs --tail 50 worker
docker compose exec -T worker python -m licence_api.delivery --once
# After correcting an explicit provider rejection, retry only still-due rejected items.
docker compose exec -T worker python -m licence_api.delivery --once --retry-rejected
docker compose restart worker
# Stop the Vite process with Ctrl+C, then stop services, retaining the volume.
docker compose down
```

To return to the standalone stack, start the API using the root README. The database schema is shared and this increment adds no migration.

## Quality gates and traceability

Run API/database gates before building. After local deployment run browser tests against the live local API and its synthetic accounts:

```sh
./scripts/test-api.sh
./scripts/test-database.sh
python3 -m unittest discover -s database/tests
python3 -m unittest discover -s mocks/xroad/tests
cd frontend
npm ci
npm run format:check
npm run lint
npm run test:unit
npm run build
npx playwright install chromium
npm run test:e2e
npm audit
mkdir -p ../artifacts
npm run --silent sbom > ../artifacts/web-dependencies.cdx.json
```

Set `PLAYWRIGHT_CHANNEL=chrome` to use installed Google Chrome, or `WEB_TEST_URL` to test another local origin. The browser suite uses disposable contexts, keyboard navigation, axe WCAG 2.1 AA checks, mobile-width views and an injected push event with all app tabs closed. Run the provider-backed manual check above to exercise actual subscription/encryption/routing. The production build output is `frontend/dist`; serve it over HTTPS with same-origin `/api` routing when testing outside loopback.
